Prima di iniziare: Git non è GitHub

Git è un programma che gira sul tuo computer e registra la storia dei file di un progetto. GitHub è un sito che può ospitare online i repository Git e aggiunge strumenti per collaborare. Puoi usare Git anche senza creare un account o collegarti a Internet.

1. I concetti fondamentali

Repository

Il contenitore del progetto

Un repository (o “repo”) contiene i file del progetto e la cronologia delle versioni registrate da Git.

Commit

Una versione salvata

Un commit è un punto nella cronologia. Contiene una fotografia delle modifiche selezionate, un messaggio e un identificativo.

Working directory

La cartella di lavoro

È la cartella in cui apri e modifichi i file. Le modifiche qui non sono ancora necessariamente incluse in un commit.

Staging area

L'area di preparazione

È il passaggio intermedio: scegli quali modifiche includere nel prossimo commit con git add.

Branch

Una linea di sviluppo

Un branch permette di lavorare su una funzionalità o un esperimento senza modificare subito il ramo principale.

Remote

Il repository remoto

È una copia del repository raggiungibile tramite rete, ad esempio su GitHub. Puoi inviare e ricevere commit.

Che cosa succede quando faccio un commit?
Git registra lo stato dei file che hai messo nell'area di staging. Non salva automaticamente ogni modifica che fai: prima controlli cosa è cambiato, poi selezioni i file con git add e infine crei il commit con git commit.
Git salva copie complete di tutti i file?
Git è progettato per registrare la storia in modo efficiente, usando oggetti e riferimenti. Per imparare, è utile immaginare un commit come una fotografia del progetto, ma tecnicamente Git riutilizza i contenuti uguali.

2. Installare gli strumenti

Windows

Scarica Git for Windows dal sito ufficiale. Include Git Bash, un terminale in cui puoi eseguire i comandi Git.

Scarica Git

macOS

Puoi installare Git tramite gli strumenti da riga di comando di Xcode oppure con un gestore di pacchetti, come Homebrew.

git --version

Istruzioni ufficiali

Linux

Usa il gestore pacchetti della tua distribuzione. Su Debian e Ubuntu, ad esempio:

sudo apt update
sudo apt install git

Per altre distribuzioni, consulta la documentazione ufficiale.

Dopo l'installazione, apri il terminale (o Git Bash) e verifica:

git --version

Se compare un numero di versione, Git è installato e il terminale lo trova.

3. Creare il primo repository

Crea una cartella

Per esempio, crea una cartella chiamata mio-progetto e aprila nel terminale.

mkdir mio-progetto
cd mio-progetto

Inizializza Git

Questo comando crea la struttura nascosta .git, che contiene i dati del repository.

git init

Crea un file

Puoi creare README.md con un editor di testo e scrivere una breve descrizione del progetto.

# Il mio progetto
La mia prima prova con Git.

Controlla lo stato

Git ti mostra i file nuovi o modificati e quelli già preparati per il commit.

git status

Prepara il file e crea un commit

git add prepara il file; git commit registra una versione nella cronologia.

git add README.md
git commit -m "Aggiunge il README"

Visualizza la cronologia

git log --oneline

Vedrai il commit appena creato e il suo identificativo abbreviato.

Nota: la prima volta Git potrebbe chiederti di configurare nome ed email. Usa un nome e un indirizzo che desideri associare ai tuoi commit:
git config --global user.name "Nome Cognome"
git config --global user.email "tu@email.com"

Queste impostazioni indicano l'autore dei commit; non creano un account online.

4. I comandi più usati

ComandoA cosa serve
git statusMostra lo stato dei file e dell'area di staging.
git add nome-filePrepara un file per il prossimo commit.
git add .Prepara le modifiche nella cartella corrente e nelle sue sottocartelle. Controlla prima cosa stai includendo.
git diffMostra le modifiche non ancora messe in staging.
git diff --stagedMostra le modifiche già preparate per il commit.
git commit -m "messaggio"Crea un commit con un messaggio descrittivo.
git log --onelineMostra la cronologia in forma compatta.
git restore nome-fileScarta le modifiche non preparate in quel file. Usalo con attenzione: non è un comando di annullamento reversibile.
git rm nome-fileRimuove un file dal progetto e prepara la rimozione per il commit.
git clone URLScarica una copia di un repository remoto.
git pullRecupera e integra gli aggiornamenti dal remoto configurato.
git pushInvia al remoto i commit locali che non sono ancora presenti lì.
Perché git add e git commit sono due passaggi distinti?
Perché puoi scegliere con precisione quali modifiche mettere insieme in una versione. Ad esempio, se hai modificato tre file ma vuoi registrare solo i primi due, aggiungi quei due file e poi crea il commit.
Come scrivo un buon messaggio di commit?
Descrivi in modo breve cosa cambia: "Aggiunge pagina contatti" è più utile di "varie modifiche". Un commit dovrebbe rappresentare un cambiamento comprensibile.

5. Branch: lavorare senza rischiare il ramo principale

Un branch è una linea di sviluppo indipendente. Spesso il ramo principale si chiama main. Puoi creare un branch per una nuova funzionalità, fare commit lì e poi integrare il lavoro.

git branch                 # elenca i branch
git switch -c nuova-funzione  # crea e passa al nuovo branch
# modifica i file e crea uno o più commit
git switch main            # torna al ramo principale
git merge nuova-funzione   # integra il branch corrente in main
Che cos'è un merge?
Il merge integra la storia di un branch in quello su cui ti trovi. Se le modifiche non si contraddicono, Git può unirle automaticamente. Se due modifiche interferiscono nella stessa parte di un file, può chiederti di risolvere un conflitto.
Che cos'è un conflitto?
È una situazione in cui Git non può decidere automaticamente quale modifica mantenere. Apri i file segnalati, scegli o combina le parti corrette, salva il risultato, poi usa git add e completa il merge con il commit richiesto da Git.

6. Lavorare con GitHub e altri siti

Un servizio online ospita il repository remoto. Il flusso tipico è: crei un repository sul sito, colleghi la cartella locale al remoto e invii i commit.

GitHub

Hosting di repository, collaborazione, issue e pull request.

github.com

GitLab

Repository Git, revisione del codice e strumenti CI/CD.

gitlab.com

Bitbucket

Repository Git e strumenti di collaborazione, spesso usati insieme ai prodotti Atlassian.

bitbucket.org

Visual Studio Code

Editor con integrazione Git grafica: puoi vedere modifiche, preparare file e creare commit.

code.visualstudio.com

Collegare un repository locale a GitHub

  1. Accedi a GitHub e crea un nuovo repository. Se hai già creato i file in locale, puoi creare il repository online senza aggiungere un README iniziale.
  2. Copia l'indirizzo HTTPS del repository dalla pagina GitHub.
  3. Nel terminale, dentro la cartella del progetto, esegui i comandi seguenti sostituendo l'indirizzo di esempio con il tuo:
git remote add origin https://github.com/tuo-utente/mio-progetto.git
git branch -M main
git push -u origin main

origin è il nome convenzionale del remoto. -u imposta il collegamento di riferimento: nelle volte successive, spesso basta git push.

HTTPS o SSH: quale scelgo?
Entrambi sono modi per autenticarti e comunicare con il servizio remoto. HTTPS è semplice da iniziare; SSH richiede la creazione e l'aggiunta di una chiave SSH al tuo account. Segui la guida ufficiale del servizio scelto e non condividere mai token o chiavi private.
Che cosa sono push, pull e fetch?
push invia i tuoi commit al remoto. fetch scarica le informazioni aggiornate senza integrarle automaticamente nel branch corrente. pull esegue il recupero e poi integra gli aggiornamenti nel branch corrente.

8. Problemi comuni e buone abitudini

“fatal: not a git repository”
Il terminale non si trova dentro una cartella Git. Entra nella cartella del progetto con cd nome-cartella e controlla che sia stata inizializzata con git init o scaricata con git clone.
“Please tell me who you are”
Configura autore e email con git config --global user.name "Il tuo nome" e git config --global user.email "tu@email.com".
Il push viene rifiutato
Il remoto potrebbe contenere commit che non hai ancora. Controlla il messaggio di errore, recupera gli aggiornamenti con git pull (eventualmente scegliendo la strategia richiesta dal progetto), risolvi eventuali conflitti e riprova. Non usare comandi forzati senza capire le conseguenze.
Ho aggiunto per sbaglio un file che non volevo nel commit
Prima del commit puoi toglierlo dall'area di staging con git restore --staged nome-file. Il file resta nella cartella di lavoro; poi controlla con git status.

Fai commit piccoli

Un commit dovrebbe contenere un cambiamento coerente e avere un messaggio chiaro.

Controlla prima di salvare

Usa git status e git diff prima di aggiungere e registrare modifiche.

Non caricare segreti

Non inserire password, token, chiavi private o file con dati personali nel repository. Usa un file .gitignore per escludere file locali.

9. Percorso consigliato per imparare

  1. Installa Git e verifica git --version.
  2. Crea un repository locale con git init.
  3. Prova più volte il ciclo status → add → commit.
  4. Crea un branch, fai una modifica e integralo con merge.
  5. Crea un repository online e prova push, fetch e pull.
  6. Impara a leggere i conflitti e a risolverli con calma.
